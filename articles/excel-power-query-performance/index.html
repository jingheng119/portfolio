Improving Excel Performance with Power Query M

A practical look at processing a 44 MB annual workbook and reducing repeated calculations.

Website edition adapted from my technical writing and examples

When spreadsheets become large, the important question is not only which formula is fastest, but how many records the workbook processes repeatedly.

Problem

A workbook containing a full year of operational records can become sluggish when many reporting formulas repeatedly scan the same source columns.

Approach

Power Query can narrow the data before the report uses it. Select the columns you need, filter early, and load a smaller result for further calculations.

let
    Source = Excel.CurrentWorkbook(){[Name="RawData"]}[Content],
    Keep = Table.SelectColumns(Source, {"Net date", "Haulage", "Item name"}),
    Filtered = Table.SelectRows(Keep, each [Net date] <> null)
in
    Filtered

The column names above illustrate the method; adapt them to your actual Excel Table.

What I observed

In one practical test, Power Query processed a roughly 44 MB, one-year dataset in around 10 seconds, compared with approximately 30 seconds for an earlier formula-based helper-sheet approach. These figures describe that workbook, not a general benchmark.

Takeaway

Reducing unnecessary work upstream often matters more than optimizing individual formulas downstream.
