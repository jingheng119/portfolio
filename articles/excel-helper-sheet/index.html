Create a Helper Sheet: Reducing Redundant Calculations in Excel

When working with a large database, we rely on a database engine to search for specific keywords, dates, or criteria before retrieving the required data for further processing. Similarly, repeatedly performing calculations directly on an entire Excel dataset can consume significant processing resources.

I encountered this challenge when trying to reduce redundant calculations in my reporting system, as I had thousands of formulas, each retrieving data from approximately 15,000 rows of monthly data. Upon closer observation, I noticed that most of the required information came from the same columns. Initially, I experimented with Name Manager to store the calculated results, but found that named formulas do not necessarily store them in memory and may require recalculation whenever the workbook recalculates. Eventually, I developed a solution by creating a helper sheet to extract the required data from the Masterlist before performing further calculations on a smaller dataset.

To create a helper sheet, we first identify the columns frequently used throughout the workbook. For example, suppose columns A, B, D, and F contain the required information, while column G contains transaction dates. We can use 

=FILTER(CHOOSE({1,2,3,4},ColA,ColB,ColD,ColF),ColG=SelectedDate)
to extract records based on the selected date and arrange them horizontally from the first day until the end of the month by repeating the formula for each date. Other worksheets can then retrieve information from the helper sheet using INDEX() with appropriate references. This reduces redundant processing and can significantly improve calculation speed.

To further improve efficiency, we can replace the formula-based helper sheet with Power Query M. First, convert the Masterlist into an Excel Table and assign it a name. Then, use Table.SelectColumns() to retain the required columns and Table.SelectRows() to filter records by month and year. Next, Table.Group() groups records by date, Table.AddIndexColumn() assigns a RowNo within each group for the subsequent pivot operation, and Table.ExpandTableColumn() expands the grouped data back into a standard table. Finally, Table.Unpivot() converts the columns into field-value pairs, while Table.Pivot() restructures the data horizontally using predefined column headers, with RowNo determining how records are aligned. Once the helper sheet is generated, other worksheets can reference its data using INDIRECT(). This produces the same report layout as the FILTER(CHOOSE()) approach through a structured transformation process.

Although Power Query M is more complex and involves more layers than conventional Excel formulas FILTER(), it is significantly faster for the overall process. The performance improvement is so substantial and appealing that it is definitely worth exploring. By dividing the processing workload into multiple helper queries, we can manage smaller operations and refresh them individually or collectively using Excel's Refresh All function.

More importantly, after introducing a helper sheet, the dataset used for calculations is reduced from the entire Masterlist (200,000 rows) to a much smaller dataset (800 rows). This makes the calculation process considerably faster and delivers outstanding performance compared to the conventional approach typically used by a normal Excel user.
